# Задача: переход на shared-inbound подписочную систему

## Суть

Вместо создания отдельного inbound (отдельный порт) на каждого пользователя —
добавлять пользователя как client внутрь общих inbound-ов (локаций).
Пользователь получает одну sub URL, которая агрегирует все локации автоматически.
Добавил новую локацию на панели → у всех пользователей сразу появился новый сервер.

## Новые таблицы БД

```
locations       — зарегистрированные общие inbound-ы (admin: /addlocation)
user_clients    — credentials пользователя (uuid, sub_id) — одна запись на юзера
user_locations  — какой юзер добавлен в какую локацию (idempotency guard)
```

## Новые команды

- `/addlocation <inbound_id> <название>` — admin
- `/removelocation <inbound_id>` — admin
- `/locations` — список локаций
- `/migrateall` — добавить всех существующих approved-юзеров в все локации

## Логика выдачи ссылки (обновлённая)

```
Если есть локации:
    Новый пользователь → add_client_to_inbound для каждой локации → sub URL
Иначе (нет локаций):
    Старый путь → create_inbound (отдельный порт) → VLESS ссылка
```

## Меры по снижению рисков

1. user_locations — проверка перед каждым add_client (idempotent)
2. Ошибка одной локации не останавливает остальные, итог репортируется
3. Старые inbound-ы не удаляются автоматически — переходный период
4. Пользователи с пустым sub_id пропускаются при миграции с предупреждением
5. /sub работает для обеих систем (user_clients и старый inbounds)
