# StelthVpnBot — документация изменений

## 2026-05-21 — /reissue_all: массовая переотправка ссылок

**Что изменилось:** Добавлена команда для переотправки актуальных VPN-ссылок всем существующим пользователям (нужно когда меняются параметры inbound-а на панели, например sni/target при переходе на Cloudflare).

**Затронутые файлы:** `bot.py`, `db.py`, `tests/test_reissue.py`

**Использование:**
- `/reissue_all` — (только админ) отправляет новую ссылку каждому пользователю у которого есть inbound; бот берёт актуальные параметры прямо с панели

**Детали:** Новая DB-функция `list_users_with_inbounds()` — JOIN users + inbounds. Задержка 0.1с между сообщениями чтобы не флудить Telegram. В конце отчёт: сколько успешно, сколько ошибок.

## 2026-05-21 — Роль модератора

**Что изменилось:** Добавлена динамическая роль модератора — назначается командой без правки `.env`.

**Затронутые файлы:** `bot.py`, `db.py`, `tests/test_moderators.py`

**Использование:**
- `/addmod <id или @username>` — выдать права модератора (только админ)
- `/removemod <id>` — забрать права (только админ)
- `/mods` — список активных модераторов

**Детали:** Новая таблица `moderators` в SQLite. Модераторы получают уведомления о заявках и могут выдавать ссылки с тем же лимитом 20 (сейчас 100, см. ниже). Только `ADMIN_IDS` из `.env` могут управлять модераторами.

## 2026-05-21 — /fix: восстановление inbound из панели

**Что изменилось:** Команда `/fix <id>` находит существующий inbound на панели по тегу или email и сохраняет его в БД.

**Затронутые файлы:** `bot.py`

**Использование:**
- `/fix <telegram_id>` — (только админ) привязать существующий inbound к пользователю

**Детали:** Полезно если inbound создан на панели вручную или запись в БД потеряна. Поиск сначала по тегу `user-<id>`, затем по email `tg_<id>`.
